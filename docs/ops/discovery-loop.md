# Discovery loop — portable spec

Recreate this as one scheduled research round per hour on whatever runtime
the operator agent has. Each run is an agent task, not a script.

## Context the worker needs

Hami is a pre-revenue project, Nepal-first: value lies in specific, local,
real-world unknowns found only through contact with reality. Loop:
REALITY → OBSERVATION → EVIDENCE → UNDERSTANDING → UNKNOWN → QUESTION →
TEST/ACTION → NEW REALITY. Never manufacture evidence. Evidence classes:
ACTUAL > OBSERVED > INFERRED > ESTIMATED > UNKNOWN; online discourse is
OBSERVED-at-best. blocked ≠ completed.

The discovery log, the unknowns map, and these rounds are OUR VERSION OF
REALITY — a model, not the territory. Reality gets the final vote.

THE MOST IMPORTANT PART — never forget: real human contact. The five
discovery conversations with real business owners are the center;
everything else is scaffolding. The loop sharpens those conversations'
questions — it never replaces them, and no round may present online
discourse as a substitute for a real voice.

## Each run

1. Read the discovery log (every angle tried before) and
   `docs/UNKNOWN_MAP.md` (unknowns banked so far). If no log exists on this
   runtime, start one at `workspace/discovery/discovery-log.md`.
2. Pick ONE tight, narrow angle NOT previously tried — small enough to
   finish well within the hour. A single trade, a single merchant tool, one
   payment rail, one neighborhood's commerce, one diaspora thread, one
   failed postmortem. Different slice each time.
3. Research public sources only (web search, social search, thread reading,
   press, public listings). Listening only: no accounts, no posting, no
   contacting real people, no fake inquiries.
4. Extract the GAIN: what changes in our version of reality? Patterns in
   people's own words (paraphrased, never invented), surprises
   (EXPECTED ≠ OBSERVED), confirmations, contradictions. If the hour yields
   nothing new, say so in one line — do not pad, do not restate old findings.
5. Bank it: append a round entry to the discovery log (brief at this
   cadence); add genuinely new unknowns to `docs/UNKNOWN_MAP.md`
   continuing the D-numbering (only when truly new); commit + push to
   `main` with a real message (docs-only commits need no test run).
6. Report the gain only — one tight message: what changed, what surprised,
   the sharpest new question. If nothing new, one honest line.

## Standing constraints

No outreach, no messaging anyone, no spending money, no intake/send-flag
changes, no production code changes without a concrete reality-driven
reason. Research and docs only. Near-zero cost: public sources only.
